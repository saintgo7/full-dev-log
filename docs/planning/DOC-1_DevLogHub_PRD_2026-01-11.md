### 3.2 기능 상세

#### FEAT-1: Git 커밋 자동 추적
- **설명**: 지정된 디렉토리의 Git 저장소에서 새 커밋을 자동 감지
- **수집 데이터**: 커밋 해시, 작성자, 이메일, 메시지, 브랜치, 저장소 경로
- **인수 조건**:
  - [ ] 30초 간격으로 새 커밋 폴링
  - [ ] 복수 저장소 동시 모니터링
  - [ ] 커밋 중복 방지 (해시 기반)

#### FEAT-2: 파일 변경 실시간 감지
- **설명**: 파일 생성/수정/삭제/이름변경 이벤트 실시간 캡처
- **지원 확장자**: `.go`, `.ts`, `.tsx`, `.js`, `.jsx`, `.py`, `.rs`, `.java`, `.md`
- **제외 디렉토리**: `node_modules`, `.git`, `vendor`, `dist`, `build`, `__pycache__`
- **인수 조건**:
  - [ ] 이벤트 디바운싱 (500ms)
  - [ ] 파일 경로 및 액션 타입 기록
  - [ ] 대용량 디렉토리 성능 유지

#### FEAT-3: 오프라인 동기화
- **설명**: 네트워크 연결 없이도 이벤트 수집, 연결 시 일괄 동기화
- **인수 조건**:
  - [ ] SQLite 로컬 저장소
  - [ ] 배치 동기화 (기본 100개/배치)
  - [ ] 실패 시 최대 3회 재시도
  - [ ] 동기화 상태 추적 (pending/synced/failed)

#### FEAT-4: 실시간 대시보드
- **설명**: WebSocket 기반 라이브 이벤트 피드 및 통계
- **인수 조건**:
  - [ ] 새 이벤트 즉시 표시
  - [ ] 에이전트 온라인/오프라인 상태 표시
  - [ ] 일별/타입별 통계 차트
  - [ ] 최근 7일 활동 요약

#### FEAT-5: 에이전트 관리
- **설명**: 복수 개발 머신의 에이전트 등록 및 관리
- **인수 조건**:
  - [ ] 에이전트 생성 (이름, OS, 머신ID)
  - [ ] API 토큰 재생성
  - [ ] 에이전트 상태 변경 (active/inactive/revoked)
  - [ ] 마지막 동기화 시간 표시

#### FEAT-6: 프로젝트 협업
- **설명**: 프로젝트 단위로 이벤트 그룹화 및 팀원 공유
- **역할**: Owner, Member, Viewer
- **인수 조건**:
  - [ ] 프로젝트 CRUD
  - [ ] 멤버 초대/제거
  - [ ] 역할 기반 접근 제어
  - [ ] 프로젝트별 이벤트 필터링

#### FEAT-7: 전체 검색
- **설명**: 이벤트 제목/내용 전문 검색
- **인수 조건**:
  - [ ] 대소문자 무시 검색
  - [ ] 이벤트 타입/날짜 필터 조합
  - [ ] 커서 기반 페이지네이션

#### FEAT-8: 터미널 명령 추적 (미구현)
- **설명**: 셸 명령어 자동 수집
- **인수 조건**:
  - [ ] bash/zsh 히스토리 연동
  - [ ] 민감 명령어 필터링 (비밀번호 포함 등)
  - [ ] 명령어 실행 디렉토리 기록

#### FEAT-9: 자동 리포트 생성 (미구현)
- **설명**: 일간/주간/월간 활동 리포트 자동 생성
- **인수 조건**:
  - [ ] 기간별 리포트 템플릿
  - [ ] 주요 활동 요약
  - [ ] PDF/Markdown 내보내기

## 4. 사용자 스토리

### USER-1 (개인 개발자) 시나리오

```
AS A 개인 개발자
I WANT 여러 머신에서의 개발 활동이 자동으로 수집되길
SO THAT 수동 기록 없이 개발 히스토리를 확인할 수 있다

Given 에이전트가 설치된 개발 머신
When  Git 커밋 또는 파일 수정이 발생하면
Then  이벤트가 자동으로 중앙 서버에 동기화된다
```

### USER-2 (팀 리더) 시나리오

```
AS A 팀 리더
I WANT 팀원들의 개발 활동을 실시간으로 확인하길
SO THAT 프로젝트 진행 상황을 파악할 수 있다

Given 프로젝트에 팀원들이 등록됨
When  대시보드에 접속하면
Then  실시간으로 팀원들의 커밋과 파일 변경을 볼 수 있다
```

### USER-3 (팀 개발자) 시나리오

```
AS A 팀 개발자
I WANT 특정 프로젝트의 이벤트만 필터링하길
SO THAT 관련 있는 활동만 집중해서 볼 수 있다

Given 여러 프로젝트에 참여 중
When  프로젝트를 선택하면
Then  해당 프로젝트의 이벤트만 타임라인에 표시된다
```

## 8. MVP 캡슐 (10줄 요약)

```
[MVP 캡슐]
1. 목표: 개발 활동 자동 수집 및 실시간 공유 플랫폼
2. 페르소나: 개인 개발자, 팀 리더, 팀 개발자
3. 핵심 기능: Git 추적, 파일 감지, 실시간 대시보드, 오프라인 동기화
4. 성공 지표: 이벤트 수집률 99%, 동기화 지연 <5분
5. 비기능 요구: 보안(JWT), 성능(2초 로딩), 안정성(99.9%)
6. Out-of-scope: 브라우저 추적, IDE 플러그인, 모바일 앱
7. 리스크: 대량 이벤트, 장기 오프라인, 동시 접속 급증
8. 완화: 디바운싱, SQLite 버퍼, 레이트 리미팅
9. 실험: 터미널 추적(FEAT-8), 자동 리포트(FEAT-9)
10. 다음 단계: Phase 2 - AI 인사이트, IDE 플러그인
```
